# RecallQuest – System Diagrams

## Project Overview

**RecallQuest** is a proposed AI-powered, gamified knowledge-retention application designed to help students remember what they learn. It monitors quiz performance, tracks topic mastery, identifies possible knowledge decay, and recommends review activities called **Review Quests**.

Students can complete review activities to improve their mastery and earn experience points (XP), levels, and streaks.

## Diagrams Included

This repository contains four basic system diagrams created using **PlantUML**.

### 1. Class Diagram
Shows the main classes of RecallQuest, their attributes, methods, and relationships. These include Student, Subject, Topic, Quiz, QuizAttempt, ReviewQuest, AIAnalyzer, and Reward.

### 2. Use Case Diagram
Illustrates how students interact with the system, including managing subjects and topics, taking quizzes, viewing mastery progress, receiving review recommendations, and earning rewards.

### 3. Activity Diagram
Represents the application's basic workflow, from student login and quiz completion to mastery analysis, review quest generation, and progress updates.

### 4. Data Flow Diagram (DFD)
Provides a basic representation of how data moves between the student, system processes, knowledge database, and external AI service.

> Note: The DFD is represented using PlantUML's available shapes and arrows. It is a simplified DFD-style diagram rather than a dedicated formal DFD notation.

## Tools Used

- **PlantUML** – for writing and rendering diagrams.
- **PlantText** or a PlantUML-compatible editor – for previewing and exporting diagrams.

## How to View the Diagrams

1. Open the PlantUML source code for the diagram you want to view.
2. Copy the code into a PlantUML-compatible editor, such as [PlantText](https://www.planttext.com/).
3. Generate the diagram preview.
4. Export the diagram as an image if needed for documentation or submission.

## Project Scope

These diagrams present a basic conceptual design of RecallQuest for academic documentation. They describe the proposed system structure and workflows and do not necessarily represent a fully implemented application.
